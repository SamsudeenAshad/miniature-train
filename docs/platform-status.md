# Platform status ledger (Step 100)

Honest account of what is proven in CI vs what needs a cluster.
Regenerated by hand when infra changes; `test_platform_status` pins the list.

## Proven in CI (static contracts)

- All manifests parse; cross-references hold (services, routes, secrets, volumes, probes).
- Fleet rules enforced: non-root, tokenless, seccomp, requests+limits, pinned images.

## Needs a cluster (unproven)

- `kubectl apply` of `infra/k8s` (Argo CD self-heal untested).
- Rollout progression + analysis runs (Argo Rollouts controller).
- Workflow execution (Argo Workflows controller).
- Prometheus/Alertmanager/Grafana/Loki/Tempo runtime behavior.
- Timed backup restore against RPO/RTO.
- Load profiles NFR-001/002/003 and 30-day SLO.

## Pilot-only stores (not production-grade)

- Postgres singleton (SPOF), MinIO singleton, MLflow sqlite+emptyDir, Tempo/Loki local disks.
- Control/inference APIs hold projects, idempotency keys, and models in memory:
  restarts lose them. A pilot Postgres-backed store is the documented next step.
